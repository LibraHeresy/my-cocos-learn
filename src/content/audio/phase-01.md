## 🧭 本节定位

打开任何一款好游戏然后关掉声音——你会立刻感觉少了什么。音频不是附属品，它是**游戏体验的三分之一**（视觉 + 交互 + 音频）。这一节帮你建立完整的音频设计思维框架。

## 🎬 故事：一个被忽略的维度

1980 年，南梦宫的《吃豆人》首次在街机厅里发出"waka-waka"的咀嚼声。在此之前，街机游戏只有零星的蜂鸣。玩家们惊讶地发现——有了声音的吃豆人，追和被追都变得更紧张了。那个简单的循环音效，让吃豆人从"一个黄色圆点"变成了"一个饥饿的生命"。

四十年后的今天，音频设计已经成为游戏开发中**最被低估的专业技能**。你会花三天调一个按钮的圆角和阴影，但可能从来没想过：为什么这个按钮按下时的声音是"咔嗒"而不是"噗嗤"？为什么击杀敌人的音效让你感到满足？为什么某些 BGM 你听了 50 遍也不烦？

答案在音频设计里。它不靠直觉——它靠原理。

## 🎯 原理：游戏音频的三根支柱

游戏音频不是"放个声音"，它是**精确的信息传递工程**。所有游戏音频可以分为三类，每一类在玩家的信息层级中占据不同位置：

**音效（SFX — Sound Effects）—— 反馈层，优先级最高**

音效是游戏对你操作的**即时回应**。你按下射击键 → 听到"biu"声 → 大脑确认"子弹已发射"。这个循环必须在 **50ms 以内**完成，否则你会感觉操作"不跟手"。这和 Web 前端的交互反馈完全一样——按钮点击后的微动画必须在 100ms 内出现，否则用户会重复点击。音效设计师的核心工作之一就是：确保每个音效的 Attack 时间足够短，短到玩家感觉不到延迟。

**音乐（BGM — Background Music）—— 氛围层，优先级最低**

BGM 定情绪的基调。它不传递即时信息，但它决定了"你现在处于什么样的世界里"。好的 BGM 你会忽略它——但你关掉它之后立刻觉得不对劲。这就像 CSS 的 `background-color`：你平时不会注意到它是 #fdf6ee 还是 #ffffff，但如果突然变成 #ff0000，你一定会警觉。

**语音（VO — Voice Over）—— 叙事层，间歇性最高优先级**

角色对话、旁白、系统提示音。语音的特点是：播放时它必须是**最清晰的**，其他声音要主动"让路"。这就像 Web 的 `<dialog>` 弹出时，背景内容被 overlay 遮住——语音就是音频层的 modal。

这三类音频在同一时刻可能同时播放（射击声 + BGM + Boss 登场语音），但它们的信息层级不同。音频设计的本质就是**管理这个动态的信息层级**——确保最重要的声音在最前面，不重要的声音往后让。

## 🔧 动手：你的第一次音频意识实验

这个实验只需要你的一部手机和你最喜欢的游戏。但请认真做——它会永久改变你对游戏音频的认知。

1. **打开你最熟悉的一款手机游戏**（或者任意你常玩的游戏），戴上耳机，**开着声音**认真玩 5 分钟。留意每一个声音出现的时机、它带给你的感觉。
2. **关掉声音**，再玩 5 分钟。同样的关卡、同样的操作。
3. 记录你的发现。至少写 **3 条**具体的体验差异。不是"感觉不一样"，而是：
   - 哪个操作变得"不完整"了？（比如击杀敌人后没有爆炸声——像 GitHub push 之后没看到绿色对勾）
   - 哪个情绪的强度被削弱了？（比如胜利画面没有音乐——像 npm install 成功但没有绿色输出）
   - 哪个信息你完全错过了？（比如背后敌人的脚步声——没有声音=没有背后感知）

这个小实验会让你亲身体验到：音频不是"配乐"，它是游戏体验不可分割的**三分之一**。你会惊讶地发现，没有声音的击杀反馈就像"一拳打在棉花上"，没有声音的胜利画面毫无成就感。

## 🔗 课外延伸

- **8-bit 时代的奇迹——限制激发创造力：** NES（红白机）的音频处理单元（APU）只有 5 个声道：2 个方波（旋律）、1 个三角波（低音）、1 个噪声通道（打击乐）、1 个 DPCM（低质量采样）。就是这 5 个声道，诞生了**近藤浩治（Koji Kondo）**的《超级马里奥》主题曲和《塞尔达传说》主题曲——游戏史上最令人难忘的旋律。近藤浩治不是音乐天才出身，他是任天堂第一批专门为游戏作曲的人。他在五声道的限制下创造了"用旋律引导关卡节奏"的设计哲学——马里奥的第一关 BGM 从简单跳跃开始，节奏随关卡推进而加速，这是游戏作曲史上的里程碑。
- **为什么限制是好东西：** 既然 NES 只有 5 个声道，作曲家就必须在"占满 5 个声道"和"留出空间给音效"之间做取舍。这种限制迫使音频设计师思考优先级——这个思维习惯在现代 3A 游戏（几百个声道可用）中依然成立。就像写 Vue 组件时 props 越少越干净一样——**限制不是敌人，是设计师的盟友**。

## ✅ 自测清单

1. 音效（SFX）、音乐（BGM）、语音（VO）在游戏中的信息层级分别是什么？当三者同时播放时，谁应该"让路"给谁？
2. 为什么音效的响应延迟必须 ≤50ms？这和 Web 前端按钮反馈的 100ms 黄金法则有什么相似之处？
3. NES 只有 5 个声道却诞生了历史上最经典的旋律。这个事实对你理解"限制在设计中是助力还是阻碍"有什么启发？

## 🧭 本节定位

分享、排行榜、激励视频广告——这三个能力合在一起，是微信小游戏能"不花广告费就把用户拉进来"的秘密。

## 📖 为什么你看到好友排行就忍不住再玩一局？

想象两个场景：

**场景 A：** 你打开一个单机飞机大战，玩到第 5 波死了，得分 3200。系统弹出"游戏结束，点击重开"。你点重开，又玩了一局。

**场景 B：** 你打开一个微信小游戏飞机大战，玩到第 5 波死了，得分 3200。系统弹出排行榜——你的好友小王 6800 分，排在你前面。下面是"分享给好友"按钮和"看广告复活"按钮。你选了一个——看广告复活，多活了 2 波，打到 7200 分，超过了小王。系统弹窗"你超越了小王！"——你截图发到了群里。

场景 B 不是假设。这就是微信小游戏的核心竞争力——**社交驱动的留存和增长**。三个开放能力构成了这个正反馈循环：**分享→好友进入→排行榜比拼→看广告→继续比拼→再分享**。这就是让你"停不下来"的飞轮。

这一节我们把这三大能力的技术实现和设计原则彻底拆开。

## 🔍 三大核心能力——技术原理与设计原则

**1. 分享（wx.shareAppMessage）——裂变的引擎。** 微信小游戏有两种分享：**被动分享**（用户点右上角"..."菜单里的"分享"，触发 wx.onShareAppMessage 回调）和**主动分享**（你在游戏里放一个"分享给好友"按钮，直接调 wx.shareAppMessage()）。

关键设计原则：**分享必须有"利他性"**。好的分享文案："快来挑战我的最高分 7200！我赌你打不到第 8 波"——有社交挑衅意味。差的分享文案："求你玩一下这个游戏"——透着乞求感。分享卡片的 imageUrl 要精心设计——用游戏内最精彩的截图，不要用 Logo。这和运营公众号文章时"标题决定打开率"是同一原理。

技术注意：wx.shareAppMessage() 不能直接在 touch 事件的回调之外调用——微信为了防止游戏"自动弹分享卡片骚扰用户"，要求分享必须由用户手势触发。这和浏览器的"requestFullscreen() 必须在用户手势中调用"的安全限制类似。

**2. 排行榜（wx.getFriendCloudStorage + 开放数据域）——竞争驱动力。** 这是微信小游戏技术上最独特的部分。排行榜的数据读取用的是 wx.getFriendCloudStorage()——它可以拿到你的微信好友中**也在玩这个游戏**的人的数据（分数、等级等）。但这里有一个隐私要求：**你不能在你的游戏主域中直接读取好友数据。** 你只能在一个叫"开放数据域"（Open Data Context）的独立 JS 环境中读取和渲染好友数据，然后通过 sharedCanvas 把渲染结果贴到主域的画布上。

为什么这么设计？如果你的游戏代码可以直接读取"你有哪些好友、他们的分数是多少"，你就可能把好友的隐私数据上传到你的服务器。开放数据域是一个沙盒——它只能访问好友关系链数据，不能访问你的游戏逻辑，也不能发起网络请求。它渲染出的排行榜画面通过 sharedCanvas 以**像素**形式传递给主域——主域拿到的是一个"图片"而不是"数据"。这和浏览器的 iframe 跨域隔离是同一个思路，但目的不是防 XSS，而是**防隐私泄露**。

**3. 激励视频广告（wx.createRewardedVideoAd）——双赢的变现。** 激励视频是免费游戏变现的黄金标准。玩家主动选择看一段 15-30 秒的视频广告，看完后获得奖励（复活、双倍金币、额外体力）。

为什么它好？因为它让**所有人都赢了**：玩家用"时间"换取"游戏内价值"（感觉做了划算交易）；广告主获得了真实的注意力；你获得了广告费（微信小游戏激励视频 eCPM 约 2-8 元）。对比强制弹出的插屏广告——把玩家的游戏体验打断，逼他看广告——结果是玩家反感。激励视频利用了行为经济学中的"心理账户"效应：玩家觉得"看广告是我主动选的"而不是"广告强加给我的"。

展示时机是关键。不要在 Boss 战中间弹广告——在死亡界面弹"看广告复活"。不要在玩家操作过程中弹——在关卡结算时弹"看广告获得双倍奖励"。你的目标是：**让玩家觉得看广告不是成本，而是选择**。

## 🔧 动手：实现完整的社交闭环

在微信开发者工具中依次实现三个能力，然后跑通整个社交循环：

1. **分享按钮：** 在游戏结束界面加一个"分享给好友"按钮。调 wx.shareAppMessage({ title: '我打了 {score} 分！你能超过我吗？', imageUrl: 'share.png' })。注意：分享回调里没有"是否分享成功"的参数（微信隐私设计——你不能追踪用户是否真的发送了分享），但分享完成后你可以给玩家一个小奖励（"感谢分享，获得 50 金币"），不管是否真的分享了——这是一种信任设计。
2. **好友排行榜：** 这是三步操作——
   - ① 在项目根目录创建 `open-data-context/` 文件夹，里面写一个独立的 JS 文件，用 wx.getFriendCloudStorage() 获取好友分数数据，然后在 sharedCanvas 上用 Canvas API 绘制排行榜列表（头像、名字、分数）。
   - ② 在主域的 Cocos 场景中创建一个 Sprite 节点，把 sharedCanvas 作为纹理贴到这个 Sprite 上——通过 `wx.getOpenDataContext().postMessage()` 向开放数据域发指令更新排行。
   - ③ 每次游戏结束时调用 wx.setUserCloudStorage({ KVDataList: [{ key: 'maxScore', value: String(score) }] }) 上传分数。
   确认：排行榜上能看到你的好友的分数和头像——这就是社交竞争驱动力的"燃料"。
3. **激励视频广告：** 在 mp.weixin.qq.com 后台开通"流量主"功能（需要满足一定条件，开发阶段可以先用测试广告位）。在游戏死亡界面加"看广告复活"按钮。调用：
   <div style="background:var(--color-surface);padding:12px;border-radius:8px;margin:8px 0;font-family:monospace;font-size:0.85em;">
   const ad = wx.createRewardedVideoAd({ adUnitId: '你的广告ID' })<br/>
   ad.load()  // 预加载，避免播放时等待<br/>
   ad.onClose(res => { if (res.isEnded) { /* 复活！ */ } })<br/>
   ad.show()
   </div>
   关键：ad.load() 要在玩家死亡**之前**调用——广告视频需要预下载，如果等玩家点了才去下载，白屏 3 秒体验极差。这和前端图片懒加载的预判逻辑一致——提前加载下一屏的图片。
4. **测试完整闭环：** 分享到群聊 → 好友点击卡片进入游戏 → 双方在排行榜上比拼 → 一方死了看广告复活 → 继续挑战记录 → 再分享。如果你能跑通这个闭环，你的游戏就具备了微信生态的核心竞争力。

## 🔗 课外延伸

- **开放数据域的本质是"隐私物理隔离"：** 开放数据域和主域之间的通信只有两个渠道：postMessage()（主域 → 开放域发指令）和 sharedCanvas（开放域 → 主域传渲染结果）。开放域不能发起网络请求，不能访问 wx.getSystemInfo()，不能操作文件系统。这个设计确保了——即使你的游戏代码是恶意的，它也无法窃取好友数据。这和银行的"双人操作"安防机制（一笔转账需要两个人审批）本质相同：**把数据的"读"和"用"分开，任何单一方作恶都无法得逞**。
- **激励视频 vs 强制广告——行为经济学视角：** Nir Eyal 的 Hook Model 里，Variable Reward（变化奖励）是第四个也是最强力的步骤。激励视频完美嵌入了这个模型：死亡是一个 Trigger→"看广告复活"是 Action→复活后能否翻盘是 Variable Reward→多活了两波是 Investment（你"投入"了 30 秒注意力）。强制插屏广告没有这个"选择"环节——用户是被打断的，感受是被侵犯的。这就是为什么现代免费游戏越来越倾向于激励视频+内购的混合变现，而不是强制广告。
- **排行榜的心理学——社会比较理论：** 1954 年心理学家 Leon Festinger 提出社会比较理论：人类有内在驱动力来评估自己的能力，而最好的参照物是**相似但稍强的人**。微信好友排行榜完美利用了这个机制——你的参照物不是全球第一的 9999999 分（太远，没有比较动力），而是你大学室友的 6800 分（很近，"我再玩一局就能超过"）。这是产品设计的精妙之处——不用任何算法推荐，社交关系本身就提供了"最有动力的比较对象"。

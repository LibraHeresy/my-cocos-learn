## 🧭 本节定位

两个游戏功能完全相同，为什么一个手感好一个手感差？**手感是几十个微小细节的叠加。** 屏幕震动、冻结帧、后坐力、音效同步——每个单独拿出来你都感觉不到，但加在一起"感觉就对了"。

## 📖 为什么你一枪打中敌人"感觉"没打到？

2019 年，独立游戏《Dead Cells》（死亡细胞）的开发团队 Motion Twin 在一次采访中被问到："你们游戏里最好玩的部分是什么？" 设计师回答："不是武器——是**每次击中敌人瞬间的那 3 帧冻结。**"

3 帧。在 60fps 下就是 0.05 秒。0.05 秒够做什么？不够你做任何事。但 0.05 秒够你的大脑处理"我的攻击命中了"这条信息。没有这 0.05 秒的冻结——你挥刀动画完成→敌人受击动画触发→伤害数字跳出→音效播放——这 4 件事"同时"发生，你的大脑来不及处理"谁在先谁在后"，感觉就是"软"。

很多游戏开发者把"手感"理解成"音效大、特效亮、屏幕抖"。但真正的"好手感"是**"玩家的动作和画面反馈之间没有认知延迟"**。你按下射击键 → 0 帧延迟子弹飞出 → 0 帧延迟命中火花 → 0 帧延迟伤害数字 → 0 帧延迟敌机阵亡动画。每一步延迟单独拿出来都不到 50ms——但加起来就是"感觉迟钝"。

这和前端动画优化中的"60fps 不是说每帧都在 16ms 内——是每一步操作都在 100ms 内给反馈"是同一个原则。你点一个按钮，100ms 内没有视觉反馈——用户就会觉得"卡"。

## 🔍 手感四大支柱——每一个单独都很小，加在一起是魔法

**1. 屏幕震动（Screen Shake）——让视觉"感受"物理。** 玩家击杀敌人后，camera 节点做一个 0.1s 的高频小振幅随机偏移（x/y 各 3-5px 振幅，easeOut）。关键细节：① 震动方向每次随机（用 Math.random() - 0.5 生成正负偏移），否则震动变成"画面平移"而不是"冲击感"。② 震幅和事件强度匹配——Boss 死亡震 8px 0.2s，小怪死亡震 2px 0.05s，像 CSS animation 有不同 keyframe 强度。③ 连续多次震动要做衰减——如果 3 帧内连续触发 5 次震动（群灭），振幅逐次降低 20%，否则画面抖到看不清。

**2. 冻结帧（Hit Stop）——给大脑 0.05 秒处理"我打中了"。** 在攻击命中瞬间，把游戏时间流速降到 0.1（director.getScheduler().setTimeScale(0.1)），持续 3-4 帧（约 50-70ms），然后恢复 1。这 50ms 的停顿让玩家的大脑有时间处理"攻击命中 → 伤害计算 → 反馈播放"这个因果链。没有冻结帧，这三个动作同时发生，像 CSS transition 没有 delay——所有变化堆在一起，眼花。

**3. 射击后坐力（Recoil / Kickback）——让动作有"重量"。** 玩家射击的瞬间，飞机向后位移 2px 再弹回。动作分解：射击触发 → tween y -= 2px（0.02s，快进）→ tween y += 2px（0.08s，easeOut，慢回）。这不只是视觉——它在告诉玩家"你刚才射了一枪"。和 CSS transform: scale(0.95) 在按钮 :active 时缩小的微交互是同一逻辑——**微小的即时反馈比任何文案都有效。**

**4. 音效同步——听觉和视觉必须"同帧"。** 如果你用 Cocos 的 AudioSource.play()，音效从触发到播放有 30-100ms 的延迟（音频解码 + 系统调度）。好的做法是：预加载所有常用音效，在触发时**已经在内存中，直接播放**。如果有条件——让音效比视觉反馈**早 1 帧**触发（音效 0ms → 冻结帧 16ms → 视觉特效 33ms）。耳朵比眼睛快——音效提前 1 帧会让玩家感觉"反应更快"。

## 🎮 输入缓冲——格斗游戏的秘密武器

你可能玩过《拳皇》或《街霸》。有没有试过：你按下 A 键想连招——但上一个动画还没播完，你的输入"被吃了"？然后你说"我明明按了啊"。

专业格斗游戏有一个设计叫**输入缓冲（Input Buffer）**：系统记住你最近 3-5 帧（约 50-80ms）内的所有按键，如果当前动画结束后这些按键能触发新动作——就执行，否则丢弃。这意味着你不需要**精确到帧**地按键——你有 5 帧的"容错窗口"。

你的飞机大战也可以受益：如果玩家按射击键太快（按住连射），系统可能来不及处理每一发。加一个 3 帧的输入缓冲队列：`inputQueue.push('shoot')` → 每帧从队列取一个执行。这消除了"我按了但没反应"的挫败感。

这和前端 debounce/throttle 处理高频事件是同样的思路——但方向相反。debounce 是"减少执行次数"，输入缓冲是**"不丢失任何一次意图执行"**。

## 🔧 动手：为飞机大战打磨手感

1. **实现屏幕震动：** 在 Camera 节点上写一个 `shake(intensity: number, duration: number)` 函数。用 tween 对 position.x/y 做随机偏移：`offset = (Math.random() - 0.5) * intensity * 2`。duration 用 easeOut（开始剧烈 → 逐渐平息）。Boss 死亡调用 shake(8, 0.2)，普通敌机死亡调用 shake(2, 0.05)。连续震动加衰减逻辑——维护一个 lastShakeTime 变量，如果距离上次震动 < 100ms，intensity *= 0.8。
2. **实现 Hit Stop：** 在敌机死亡函数中，用 `director.getScheduler().setTimeScale(0.1)`，设置一个 3 帧（0.05s）的延迟后恢复 scale 为 1。注意：不是全部时间流速都降——只降游戏逻辑时间（setTimeScale 只影响 Scheduler 管理的定时器/动作，不影响组件 update、粒子与 tween——实际项目中常用它做慢动作/冻结帧，但要注意生效范围），UI 层的动画和 tween 不应该被冻结。如果不好隔离——把 Hit Stop 改成"在命中位置生成白色闪光帧 + sprite 膨胀 10% 再缩回"，用 tween 实现同样效果。
3. **实现射击后坐力：** 在射击函数中，对飞机的 position 做 tween：to(pos.y - 2, 0.02) → to(pos.y, 0.08, { easing: 'backOut' })。两个要点：① 飞机正在移动时（玩家手指拖动）——后坐力和移动叠加，不要用 setPosition 覆盖移动，用"在当前位置基础上的偏移"（tween by 而不是 to）。② 连射时——如果前一发后坐力动画还没结束，叠加偏移（y -= 2 再减 2），不能取消前一个 tween。
4. **对比测试：** 关掉以上三个效果，玩一局——记下"感觉"。打开全部效果，再玩一局——记下"感觉"。游戏规则完全没变，但第二次你会觉得"更爽"。这就是手感的魔力——**它不改变游戏，它改变"玩游戏的体验"。** 和 Cocos 课程 Phase 8 的缓动曲线（easing）调试一样——同样的动画时长，不同的 easing 曲线，感觉完全不同。

## 🔗 课外延伸

- **《合金弹头》——屏幕震动的先驱：** 1996 年 SNK 推出的《合金弹头》是最早大规模使用屏幕震动的游戏之一。每次手榴弹爆炸、坦克开炮、Boss 登场——整个屏幕都在抖。这不是技术限制（Neo Geo 主机性能足够稳定）——是为了**让玩家的身体感受到"爆炸"**。《合金弹头》的屏幕震动是有方向性的——爆炸在屏幕右边，震动也略微偏向右边。这和现实世界中爆炸的冲击波有方向性一样——这种"物理上不可能但心理上成立"的细节就是手感设计的精髓。
- **《鬼泣》的打击感——逐帧调试的极致：** CAPCOM 的动作游戏《鬼泣》系列被公认为"打击感教科书"。它的 Hit Stop 不是固定的 3 帧——不同武器有不同的冻结时长：长剑 3 帧，巨斧 6 帧，双枪连射每发 1 帧。Hit Stop 期间，敌人会"僵直"（停滞在当前帧），但剑身继续移动（轨迹线继续渲染），然后敌人身体震动+火花+音效三合一。每把武器的 Hit Stop 曲线都是**逐帧手动调参**出来的。这是手感打磨的终极形态——不是"加个效果就完了"，是"每一帧都在雕琢"。
- **输入缓冲不只在格斗游戏——在所有的"快节奏操作"中：** 从《塞尔达传说：旷野之息》的"盾反"（3 帧缓冲窗口）到《守望先锋》的技能队列（上一个技能释放中按下一个——会在前一个结束后立刻执行），输入缓冲是消除"我明明按了"挫败感的终极武器。它的代价是"可能执行玩家'不小心'按的键"——所以缓冲窗口不能太长，3-5 帧是黄金区间。

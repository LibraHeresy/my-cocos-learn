## 🧭 本节定位

基础技法你已经掌握了。这一节讲几个"非必须但用了就飞升"的技巧——**调色板替换（Palette Swap）、像素粒子和镜面反射**。这些不是"基础"，但它们是让你从"会画"到"画得好"的跳板。

## 🔄 超级马里奥的 Luigi 就是 Mario 换了个色——游戏史上最省美术的技巧

1985 年，任天堂发布《超级马里奥兄弟》——但你可能不知道的是，游戏的 2P 角色 Luigi 并没有一套独立的精灵图。Luigi 就是 Mario 的精灵图，只是把红色/蓝色换成了绿色/白色。同一套 16×16 的像素数据，一个调色板的替换就创造了一个"新角色"。

这不是"偷懒"——这是**调色板替换（Palette Swap）**——像素画最高效的技法之一。原理极其简单：

- 你的像素画里每个像素存储的不是颜色值——而是**调色板索引（Palette Index）**。索引 0="深蓝"，索引 1="中蓝"，索引 2="浅蓝"，索引 3="高光白"。
- 调色板替换就是把索引没变、但每个索引对应的颜色值改了。索引 0 变成了"深红"，索引 1 变成了"中红"，以此类推。
- 结果：**形状完全不变，但视觉上从一个"友方飞机"变成了"敌方飞机"**。

这和前端开发的"设计令牌（Design Token）换肤"一模一样的思路：你的 Vue 组件里所有的 `color: var(--color-primary)`，你不需要改组件代码——你只需要把 `--color-primary` 从蓝色换成红色，整个应用就换肤了。像素画的调色板替换——就是 CSS 变量的换肤方案，只不过作用在像素索引上。

在 Aseprite 中做调色板替换非常简单：调色板面板 → 新建一个调色板（比如"enemy-red"）→ 内容颜色和"player-blue"调色板一一对应但色相不同 → Edit → Color Quantization → 选择新调色板 → 一行代码不写，整个精灵瞬间"叛变"。

在引擎层面——Cocos 可以用 Shader 实现运行时调色板替换（Cocos 课程的 Phase 21 会覆盖），这意味着**你的游戏可以在运行时动态切换角色的颜色方案**。同一套角色动画，白天用蓝白色调，夜晚用橙红色调，被诅咒时用紫色调——全都是"同一套精灵图+不同的调色板"。这是 2D 游戏中性价比最高的视觉多样性方案。

### 像素粒子——用 2×2 的小方块炸出天女散花

Phase 10 你画了爆炸特效的逐帧动画——那是为"固定场景"设计的。但当你有 50 颗子弹需要各自独立的小火花时，逐帧动画就不现实了。这时候你需要**像素粒子**——用 1-3px 的小色块作为粒子的"基础贴图"，靠粒子系统的参数生成无穷变化：

- 粒子的贴图：一个 4×4 的 PNG，包含 2-3 个不同颜色的 1-2px 小点。比如 2 个白点和 1 个黄色点。
- 粒子系统的参数控制：发射速率（每秒出多少粒子）、生命周期（每个粒子活多久 → 颜色渐变）、速度方向和随机范围（粒子往哪飞）、重力（粒子怎么下落）。
- 颜色渐变：粒子出生时是白色/亮黄色（高温），逐渐变成橙色、红色、暗红（冷却），最后淡出死亡。

像素粒子和传统粒子的核心区别：**像素粒子用"正方形"的 1-3px 小块，没有模糊边缘**。这和游戏的像素画风格完全一致。如果用了带抗锯齿边缘的粒子贴图（比如一个模糊的圆形光点）——它放在像素画场景里会立刻"跳"出来——因为它是你这游戏里唯一"看起来糊"的东西。风格一致性远比你想象的重要。

### 镜面反射——把场景翻过来，就是水面

如果你想让游戏的某一关有水面或镜面地板——不需要重画一套。把上面的场景垂直翻转（Flip Vertical），调整颜色（让倒影比原场景颜色暗 20-30%、饱和度降低），就是"反射"。这个技巧在《铲子骑士》的镜面关卡和大量像素平台游戏中都能看到。

## 🔧 动手：调色板替换 + 像素粒子参考

两个实验——不需要很长时间，但会让你对"高效"有全新的理解。

### 实验一：调色板替换（10 分钟）

1. 打开你之前画的玩家飞机 .aseprite 文件（或任何已有角色）。
2. 在调色板面板中，点击左上角菜单 → Save Palette → 命名为 "player-blue"。这保存了你当前的调色板。
3. 点击菜单 → New Palette → 命名为 "enemy-red"。
4. 在 "enemy-red" 调色板中创建和 "player-blue" 相同数量的颜色——但色相分别偏移约 180°（蓝→红方向）。保持明暗阶梯一致（最暗→最亮的相对关系不要变）。
5. 点击菜单 → Color Quantization → 选择 "enemy-red" → OK。
6. 观察——你的飞机从蓝色瞬间变成了红色！但所有的形状、明暗、线条——保持完全一致。这就是"同一套精灵，N 套视觉"。
7. 撤销（Ctrl+Z），回到原色。再试一次——这次做一个"被冰冻"的蓝色版（色相偏蓝+明度提高+饱和度降低）和"被诅咒"的紫色版。

### 实验二：像素粒子参考图（15 分钟）

1. 新建 32×32 画布，背景透明。
2. 用铅笔随机点出 20-30 个 1-2px 的小点，分布在整个画布上。不要集中在一处——散开，但中心区域密度稍高（模拟"从中心爆发"）。
3. 给这些点分配颜色以模拟温度分布：中心 6-8 个点亮黄色（#ffff00，核心温度最高）。中间环 8-10 个点橙色（#ff8800）。外围 6-8 个点红色（#ff3300，外缘冷却）。最外面零星几个点暗红（#cc0000）。
4. 导出为 `particle_ref.png`。这个文件不是直接使用的 SpriteSheet——它是**参考**，帮你记住"像素粒子的颜色分布和密度该是什么样"。实际做粒子贴图时，你只需要几个 1-2px 的点（比如一张 8×8 的图，里面只有 2-3 个小点）作为发射器的"基础粒子形状"。

这两个实验的共同哲学：**用最少的像素+颜色的变化创造视觉多样性**。调色板替换 = 形状不变颜色变。像素粒子 = 形状随机颜色渐变。两件事合起来——你已经掌握了像素画高效创作的半壁江山。

## 🔗 课外延伸

- **《合金弹头》的像素粒子美学：** SNK 的《合金弹头》系列是 2D 射击游戏中视觉细节的顶峰——爆炸时飞出的碎片不是"几个点"，而是**几十个有明确形状的碎片**：螺丝、铁板碎片、木桶残骸。每一个碎片都是手绘的像素精灵，在粒子系统中随机选取和旋转。这就是"像素粒子"的终极形态：不是通用的"光点"，而是有主题的碎片。对于你的飞机大战——可以考虑画 3-5 种不同形状的"金属碎片"像素图（三角、矩形、L 形 3-4px），让爆炸看起来是"敌机碎裂"而不是"光球爆炸"。
- **Shader 换色 vs Palette Swap——运行时和设计时的分工：** Aseprite 中的调色板替换是"设计时"（你在做资产的时候就决定了颜色方案）。Cocos Shader 换色是"运行时"（游戏运行中根据状态动态替换）。两者不是替代关系——是分工关系：**设计时调色板 = 你的视觉设计工具。运行时 Shader = 引擎的动态效果工具。**学会在 Aseprite 中规划调色板索引，在 Cocos 中用 Shader 读取这些索引——你的工作流就打通了。
- **像素画"对称"的两种实现：水平镜像 vs 真正的调色板对称：** 很多 2D 游戏用"水平翻转"（Flip X）来做角色转身——左边跑的面朝左，翻转到右边面朝右。这节省了 50% 的精灵帧制作量。但做翻转的时候要注意：如果光源在左上 45°——翻转后光源变成了右上 45°，方向错了。这时候有两种做法：要么接受翻转的光源不一致（大部分游戏都接受了因为玩家注意不到），要么画两套分别面左和面右的帧（像素画师的纯粹主义）。对于你的飞机大战——飞机是对称设计的所以不存在光源问题，但如果是人形角色就要考虑了。

## ✅ 自测清单

1. 调色板替换为什么能"一行代码不改就让一个角色变阵营"？从数据存储（索引 vs 颜色值）的角度解释它的底层原理。
2. 像素粒子和传统粒子贴图的区别是什么？为什么像素游戏中的粒子必须用"没有抗锯齿"的小方块？
3. 如果你做了一个"水平翻转"的角色从左边转到右边——光源方向从左上变成了右上。玩家会注意到吗？如果注意到了，你会怎么办？

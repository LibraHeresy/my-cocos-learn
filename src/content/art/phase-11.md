## 🧭 本节定位

角色在太空里飞——太空是什么？是黑屏加上几个白点吗？**好的背景不抢戏——它让你沉浸但不分散注意力**。本节讲怎么画飞机大战的三层背景，并在 Cocos 中实现视差滚动——让你的 2D 画面有空间深度。

## 🌍 1982 年，一个街机游戏发明了 2D 世界的"深度"

1982 年，日本街机厂商 Irem 发行了《Moon Patrol》——玩家驾驶月球车在坑坑洼洼的月球表面行驶，躲避石头和弹坑。这个游戏在今天看来非常简陋，但它做了一件在 1982 年极为超前的事：**它让背景的三层以不同速度滚动**。

远处的山脉移动最慢，中间的山丘移动中速，近处的地面移动最快。玩家坐在街机前，体验到了一个前所未有的感觉——"这个 2D 画面有深度！"这个技法后来被命名为**视差滚动（Parallax Scrolling）**，并从此成为 2D 游戏空间深度表达的标准方案。从《超级马里奥》到《蔚蓝》到《空洞骑士》——所有让你觉得"2D 世界好广阔"的游戏，几乎都用了视差滚动。

视差滚动的物理原理非常简单——你每天都体验到它：坐在行驶的汽车里，看向窗外。近处的电线杆飞速掠过，远处的山峰几乎一动不动。这就是视差——**越近的物体视觉移动越快，越远的物体视觉移动越慢**。你的大脑自动从这个速度差中推算出空间深度。

在游戏里，你不需要真正的 3D 场景来创造深度——你只需要把画面分成若干层，让它们以不同速度移动。这就是 2D 游戏空间感的魔法。

## 🎨 三层架构 + 色彩透视：空间深度的两个支柱

### 第一支柱：前 / 中 / 远三层

你的飞机大战背景至少需要三层——不是"好看的需求"，是**空间信息的结构需求**：

- **远景层（Far Layer）—— 最慢移动：** 天空底色、最远的星云、极远处的山。颜色最淡、最不饱和、偏向蓝灰（大气散射的物理效应——远处的物体看起来更蓝更淡）。你用这一层来"定调"——冷色=太空/夜晚，暖色=落日/黄昏。
- **中景层（Mid Layer）—— 中等速度：** 云朵、中等距离的山脉、星云的大块结构。颜色饱和度比远景略高，但依然"退后"。中景层是"过渡层"——在远景和近景之间建立视觉桥梁。
- **近景层（Near Layer）—— 最快速度：** 前景的地面、树木剪影、建筑物轮廓。颜色最深、饱和度最高、边缘最清晰。近景层元素偶尔可以"闯入"画面边缘来加强纵深感——比如画面底部一条快速掠过的地平线或岩石带。

### 第二支柱：色彩透视（Atmospheric Perspective）

这不止是"远处的东西颜色淡"——它是被物理学支撑的视觉规律。大气不是完全透明的——它含有水蒸气、尘埃、微粒。光在穿过大气时会发生散射（Rayleigh Scattering 瑞利散射），短波长的蓝光散射最严重。所以远处的物体——

- 颜色向蓝色偏移（因为蓝光散到了你的眼睛里）
- 饱和度降低（因为散射光"稀释"了物体的本色）
- 对比度降低（因为亮区和暗区的差异被散射光"填平"了）

在像素画中应用色彩透视非常简单：远景层用最高的蓝色值+最低的饱和度。近景层反过来——用最低的蓝色值+最高的饱和度+最高的对比度（清晰的边缘）。三层之间的色彩阶梯就是"深度"。这和你在 CSS 中给不同 `z-index` 的元素加不同的 `opacity` 和 `filter: blur()` 来营造深度感是同一个逻辑。

### 重复纹理 vs 手绘独特区域

对于无限滚动的背景（比如飞机大战的星空），你需要**可平铺的纹理**——一张图重复拼接不会露出接缝。在 Aseprite 中用 Tiled Mode（View → Tiled Mode → Tiled in Both Axes）预览平铺效果。画的时候注意左右边缘和上下边缘的像素要能无缝对接。

对于固定的场景（比如菜单背景或关卡背景），不需要平铺——手绘独一无二的区域更有质感。关键判断：**这个背景需要"无限滚动"还是"只展示一次"？**

## 🔧 动手：画三层背景 + 在 Cocos 中实现视差滚动

先画，再搭——两个阶段都要亲手操作。

### 第一阶段：在 Aseprite 中画三层背景

1. **新建 Aseprite 文件：** 256×256 画布。这足够大来做平铺测试。
2. **远景层（far）：** 新建图层"far"。用最淡的颜色——深蓝底（接近夜晚天空），随机散布 1px 的白点和浅蓝点做星星。星星密度约 5%（每 20 个像素里有 1 个星点）。不要均匀分布——随机但有簇有疏。远处画一些极简的山脉剪影——只用 1 个浅蓝灰色，2-3 像素高的起伏弧线。山脚加轻微渐变（1px 的稍暗色做山脚阴影）。
3. **中景层（mid）：** 新建图层"mid"。用中等色调画云朵——4-6 像素直径的不规则团块，边缘有轻微的"凹凸"（±1px 的不规则边缘模仿蓬松感）。画 5-6 朵不同大小的云，分布在不同高度。云朵用白+浅蓝灰两种颜色做细微的立体感。
4. **近景层（near）：** 新建图层"near"。用最深色调画近处的地面元素。比如画面底部 64px 高的地带——不规则的地面岩石轮廓、可能有一些建筑物的剪影（雷达天线、信号塔——用 1px 深色线条勾勒轮廓）。近景层的元素用最清晰的边缘。
5. **检查平铺：** View → Tiled Mode → Tiled in Both Axes。检查三层各自的接缝——左右和上下边缘的像素是否一致？如果某一层出现明显的"网格线"——那就是纹理不平铺，需要修边缘。
6. **分别导出三层：** 每次只显示一个图层（隐藏另外两个），File → Export → 分别保存为 `bg_far.png`、`bg_mid.png`、`bg_near.png`。

### 第二阶段：在 Cocos 中实现视差滚动

1. **导入资源：** 把 3 张 PNG 拖入 Cocos 的 `assets/textures/background/` 目录。在 Inspector 中，所有贴图的 Filter Mode 必须设为 **Point**（像素画铁律）。
2. **创建场景节点：** Canvas 下创建 3 个 Sprite 节点——分别命名为 `bg_far`、`bg_mid`、`bg_near`。把对应贴图拖入 SpriteFrame。把它们的 Size 设为和 Canvas 一样或稍大（保证滚动时不会露边）。
3. **编写视差滚动脚本（伪代码）：**

<pre>// ParallaxScroll.ts - 挂到每个背景 Sprite 上
@property speed: number = 50; // 滚动速度

update(dt: number) {
  // 向左滚动（飞机向右飞 = 背景向左移）
  this.node.x -= this.speed * dt;
  // 当背景完全滚出屏幕左侧时，重置到右侧（循环）
  if (this.node.x <= -bgWidth) {
    this.node.x += bgWidth;
  }
}</pre>

   给三个背景节点分别挂这个脚本，设置不同的 speed：远景 speed=10、中景 speed=30、近景 speed=60。数字不必精确——直接决定了三层之间速度的比例关系。远景最慢，近景最快。
4. **（进阶）双 Sprite 交替无限滚动：** 上述方案是"移出屏幕后重置"——在重置瞬间会有画面跳动。专业做法：为每一层创建**两个相同的 Sprite**，并排放置。当第一个 Sprite 完全滚出屏幕后，立刻放到第二个 Sprite 的右侧。这样永远没有"跳帧"——这是所有 2D 游戏背景滚动的标准写法。

做完这两大阶段，运行你的 Cocos 场景——你应该看到三层背景以不同速度向左滚动，创造出强烈的空间纵深感。这就是视差滚动的魔法。

## 🔗 课外延伸

- **"HD-2D"——《八方旅人》的空间魔术：** Square Enix 的《八方旅人》（Octopath Traveler）开创了一种叫"HD-2D"的视觉风格：角色和环境是 2D 像素精灵，但光照和阴影是 3D 引擎实时计算的。这意味着一个 16×16 的像素角色走进树荫下时，它的像素颜色会实时变暗。这种"2D像素+3D光影"的混合手法打破了"像素画=平面"的刻板印象——证明像素画和现代光照技术可以共存，而且极其惊艳。如果你好奇像素画表现力的边界在哪——去搜一段《八方旅人》的游戏画面，你会被震撼。
- **视差滚动的物理——为什么你看到的不是 bug：** 视差（Parallax）这个词来自希腊语 `parallaxis`——意思是"交替"。在光学中它指的是——从不同角度观察同一个物体时，物体在背景上的视觉位置会不同。这就是为什么你轮流闭左右眼时，手指看起来"跳"了一下。游戏中的视差滚动复制了这个物理现象：不同速度的背景层模拟了"不同距离的物体在你移动时视觉速度不同"的真实世界规律。当你用游戏引擎写的视差代码时——你其实是在模拟人类视觉系统的深度感知机制。
- **和前端"视差滚动"的同源：** 作为前端工程师你可能见过网页的视差滚动效果（一个网页滚动时背景固定不动或移动速度不同）。游戏的视差滚动和网页的视差滚动——底层是同一个原理：**让不同层以不同速度响应同一个"滚动"输入**。区别在于游戏是实时循环驱动的（可能 60fps 持续滚动），网页是事件驱动的（只在用户滚动时响应）。

## ✅ 自测清单

1. 视差滚动为什么能创造深度感？试着从物理学的"观察者移动 + 物体距离差异 → 视觉角速度差异"的角度解释。
2. 三层背景（远/中/近）除了速度不同，在颜色上应该有什么差异？如果三层颜色完全相同——只靠速度差异够不够？为什么不够？
3. 平铺纹理的"无缝性"怎么检查？如果你在 Aseprite 里画了星空但没检查平铺——在游戏中会出现什么视觉效果？
